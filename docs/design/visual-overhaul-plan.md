# ZeppBridge 前端视觉与设备 UI 改造计划

> 更新：2026-08-15（重构里程碑完成）。记录系统实现事实与规范定义，全链路贯彻军事绿暗色设计系统与数据安全底线。

## 目标

建立一个数据优先的健康工作台：层级清晰、状态完整、语义颜色稳定，让设备识别、健康时序和 AI 交接三个概念彼此独立。概览、导出与提示词、最近记录、睡眠/运动详情以及设置页面共享同一套设计令牌与设备模型。

## 已落地重构范围

### 1. 视觉系统与设计令牌 (P1)
- **色彩底座**：军事风近黑橄榄色系。`--bg: #12140D`、`--canvas: #14160C`、`--surface: #1B1E12`、`--surface-raised: #22261A`、`--surface-hover: #2B3120`。
- **品牌与重点**：`--brand: #CDDC7C`、`--accent-ink: #181B0E`、`--accent-soft: rgba(205, 220, 124, 0.12)`。
- **健康语义色（对齐 Zepp）**：
  - 心率：`#F0616A`
  - 配速 / 距离：`#4AA8E8`
  - 海拔 / 警告：`#F5C33B`
  - 消耗 / 功率：`#F5860B`
  - 训练 / 就绪：`#3DD84C`
  - 步态 / 活动：`#2BB3C0`
- **睡眠阶段色**：
  - 深睡：`#7B4FB3`（深紫）
  - 浅睡：`#7C8FF0`（浅蓝紫）
  - REM：`#2FA96B`（绿）
  - 清醒：`#E84C3D`（红）
- **精细滚动条与动效**：全局 `::-webkit-scrollbar` 细条（4px）、轻量 opacity/transform 动效，支持 `prefers-reduced-motion` 降级。
- **品牌名称规范**：全局修正为 `ZeppBridge`，云端服务统一标记为 `Zepp Cloud`。

### 2. 探索页重构 (P2 - `Overview.vue`)
- **Hero 价值区**：展示三大价值卡（安全、私密、AI-ready）以及清晰的数据流转链条（Zepp Cloud → ZeppBridge → AI 工具）。
- **设备与云状态卡**：左侧展示已识别实体设备及 Zepp Cloud 服务状态；右侧展示最新数据包时序范围、记录总数及各数据流就绪状态。
- **AI 交接就绪度**：圆环就绪度进度条（`CircularProgress`）+ 4 项数据流检查 + 快速操作；底部固定 4 项安全承诺横条。

### 3. 导出与提示词页 (P3 - `Explore.vue`)
- **日历组件**：自绘深橄榄底日历弹层选择器，支持 7 天 / 30 天快捷切换与按月点选。
- **界面收敛**：移除冗余的 JSON 预览大代码块与非必要阻拦弹窗，默认执行不可逆脱敏直接复制。
- **超限直出**：数据包体积 > 2 MiB 时，后端自动写入桌面 `zeppbridge-ai-handoff.json` 并向剪贴板发送提示。

### 4. 设置页重构 (P4 - `Settings.vue`)
- **网格布局**：采用 2 列 + 3 列卡片网格。
- **默认导出格式持久化**：`zeppbridge-default-export-format` 本地存储联动。
- **清理死控件**：移除无实际后端支持的开关与按钮，隐私政策弹窗就地展开说明。
- **锚点完善**：支持 `#account-section` 与 `#privacy-section` 锚点直达。

### 5. 历史记录与详情页 (P5)
- **最近记录 (`RecentRecords.vue`)**：统一两列行高与“共 N 条”计数口径；隐藏不完整数据时显示明确透明提示。
- **运动详情 (`WorkoutDetail.vue`)**：ECharts 图表统一走主题注册，面积垂直渐变 + 虚线均值线；本地 GPS 画布按速度色谱着色；心率区间条与客观统计。
- **睡眠详情 (`SleepDetail.vue` / `StageBar.vue`)**：采用深紫/浅蓝紫/REM绿/清醒红阶段色；新增近 7 天每日睡眠时长分期堆叠周柱状图。

### 6. 数据层修复 (P6)
- **运动明细类型扩展**：扩展 `pending_running_details` 匹配规则，支持所有带有 `zepp_source` 的户外运动拉取逐点明细。
- **增量同步窗口扩展**：默认增量同步由 7 天扩展至 30 天，保证时序连贯。
- **容错强化**：单项明细拉取失败记录警告日志并不阻断整体流程。

## 验收顺序

1. 运行 `npm run build`，确认 TypeScript 类型与 Vite 构建通过。
2. 运行 `cargo check`，确认 Rust 后端编译通过。
3. 检查各界面响应式与暗色主题一致性。
