# ZeppBridge UI 设计与交互约束

更新时间：2026-08-13。Bridge 是数据桥梁，不是分析 App。视觉借鉴健康类 App 的分类色和数字层级，不复制第三方资产。强调色是低饱和绿 `#3DDC84`，不要用系统蓝。

## 核心原则

- 同步可信：云端拉取时间、同步结果和健康样本时间必须分开表达。
- 真实优先：缺失值显示 `—` 或明确空状态，不用零值、模拟曲线或估算地图填空。
- 分析外置：解读交给用户自己的 AI。应用只存数据、给简洁概览、导出 JSON。
- 操作收敛：日常同步只有顶部和设置页的「立即同步」；历史补拉属于高级维护。
- 渐进披露：已连接时连接区只留状态和同步；网页登录入口在未连接或需要重连时出现。诊断、重解析和清理默认折叠。
- 品牌强调仍是低饱和绿（按钮、同步、焦点）。心率红、睡眠蓝、运动绿只用于对应分类，不另做第四套 CTA 色。黄色只代表确实需要关注。
- 颜色只用 hex / 已有 CSS 变量；页面样式跟 `App.vue` 的 token，不要各页再发明一套近黑壳。

## 页面层级

主导航三项：概览、交给 AI、设置。睡眠/运动不进主导航；概览「查看全部」进入 `/sleep`、`/workouts`。单条详情仍从列表或概览记录进入。

### 概览

1. 短页头与云端同步时间；
2. 心率主数字、真实样本时间；有 24 小时真实点才画 sparkline；
3. 「交给 AI」入口；
4. 最近最多 3 条睡眠、3 条运动。

恢复度、HybridCharge、训练负荷墙和训练负荷柱图不进概览。这些字段只出现在导出 JSON 或单条详情里（若该记录确实有值）。

概览同步后自动重读本地数据。加载失败时保留明确重试。

### 交给 AI

独立页 `/ai`。默认最近 7 天，可改日期和类型。动作：复制 JSON（主）、保存文件、更新本机 `exports/zeppbridge-ai-feed.json`。没有记录时不把空壳当成成功。设置页不再放导出。

### 睡眠与运动

- 列表：`/sleep`、`/workouts`，用与概览相同的 `RecordRow` 和 token。
- 详情：`/sleep/:sleepId`、`/workouts/:workoutId`。
- 睡眠：总时长、入睡/醒来、评分，以及深睡、浅睡、REM、清醒的真实时长和比例。
- 运动：类型、时间、时长、距离、热量、平均/最高心率、训练负荷和 VO₂max；只在距离和时长均有效时计算配速。
- 没有运动采样、路线或完整睡眠时间轴时，不渲染空图表或虚构内容。

### 设置

1. Zepp 网页登录 / 连接状态与立即同步；
2. 保留天数与历史补拉；
3. 应用打开期间的 15 分钟自动同步开关；
4. 跟随系统、浅色、深色；
5. 「高级与隐私」折叠区（诊断、本地数据维护）。不含导出。不含证书或代理步骤。

已保存且未明确失效的认证显示绿色「已连接」。只有 401/403 或 `needs_reauth` 显示红色并展开重新连接入口。

## 状态语义

| 状态 | 颜色与文案 |
| --- | --- |
| 已连接 / 已同步到新数据 | 绿色 |
| 空闲 / 已保存 / 云端暂无新数据 | 灰色或普通正文 |
| 部分数据流失败、需要用户留意 | 黄色 |
| 认证失效、同步失败 | 红色 |

顶部与设置页必须复用同一个同步控制器状态。清除或更换认证后必须重建反馈，不能残留旧账号的「已更新/失败」。

网页登录状态：`idle` / `waiting` / `extracting` / `verifying` / `connected` / `failed`。进行中时设置页显示取消；失败时显示重试。

## 主题、响应式与可访问性

- 自定义主题菜单支持鼠标、方向键、Home/End、Esc、点击外部关闭和持久化，不使用白底原生 `<select>`。
- `760px` 以下切换为移动顶栏与底部三栏导航；各页面不得产生横向溢出。
- 交互控件维持可用触控面积、`focus-visible`、语义按钮/链接、`role=status/alert` 和 `aria-live`。
- 尊重 `prefers-reduced-motion`，动画只用于短暂同步、菜单或加载反馈。

## 发布前仍需人工检查

- 安装版浅色、深色、跟随系统三态及重启持久化；
- 760px 和常用桌面窗口的滚动、折叠区与键盘顺序；
- 真实网络失败、401/403、部分流失败与空数据状态；
- 屏幕阅读器与颜色对比；
- 产品图标、安装包签名和任务栏标识。
