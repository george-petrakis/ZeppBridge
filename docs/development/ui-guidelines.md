# ZeppBridge UI 设计与交互约束

更新时间：2026-08-13。当前界面借鉴健康应用的“概览 → 分类列表 → 单条详情”层级和渐进披露，不复制第三方视觉资产。

## 核心原则

- 同步可信：云端拉取时间、同步结果和健康样本时间必须分开表达。
- 真实优先：缺失值显示 `—` 或明确空状态，不用零值、模拟曲线或估算地图填空。
- 操作收敛：日常同步只有顶部和设置页的“立即同步”；“重新同步最近 30 天”属于高级维护。
- 渐进披露：已连接时隐藏代理与认证教程；诊断、导出、重解析和清理默认折叠。
- 单一低饱和绿色作为品牌强调。黄色只代表确实需要关注，不用于“已保存”或“云端暂无新数据”。

## 页面层级

### 概览

概览按以下顺序组织：

1. 最新心率主信息及真实样本时间；
2. 云端同步、心率样本、本地覆盖和来源；
3. 今日活动、训练状态、恢复与健康；
4. 可点击的最近睡眠和运动记录。

不再使用大量等权大卡片。概览同步后自动重读本地数据，不提供容易混淆的常驻“本地刷新”按钮；加载失败时保留明确重试。

### 睡眠与运动

- 列表记录整行可点击并有方向提示。
- 睡眠详情展示日期、入睡/醒来、总时长、评分，以及深睡、浅睡、REM、清醒的真实时长和比例条。
- 运动详情展示类型、时间、时长、距离、热量、平均/最高心率、训练负荷和 VO₂max。
- 没有运动采样、路线或完整睡眠时间轴时，不渲染空图表或虚构内容。

### 设置

默认单页顺序为：

1. Zepp 连接状态与立即同步；
2. 应用打开期间的 15 分钟自动同步开关；
3. 跟随系统、浅色、深色；
4. “高级与隐私”折叠区。

已保存且未明确失效的认证显示绿色“已连接”。只有 401/403 或 `needs_reauth` 显示红色并展开重新连接入口。逐流状态使用纵向行，技术记录数只在展开详情出现。

## 状态语义

| 状态 | 颜色与文案 |
| --- | --- |
| 已连接 / 已同步到新数据 | 绿色 |
| 空闲 / 已保存 / 云端暂无新数据 | 灰色或普通正文 |
| 部分数据流失败、需要用户留意 | 黄色 |
| 认证失效、同步失败 | 红色 |

顶部与设置页必须复用同一个同步控制器状态。清除或更换认证后必须重建反馈，不能残留旧账号的“已更新/失败”。

## 主题、响应式与可访问性

- 自定义主题菜单支持鼠标、方向键、Home/End、Esc、点击外部关闭和持久化，不使用白底原生 `<select>`。
- `760px` 以下切换为移动顶栏与底部导航；各页面不得产生横向溢出。
- 交互控件维持可用触控面积、`focus-visible`、语义按钮/链接、`role=status/alert` 和 `aria-live`。
- 尊重 `prefers-reduced-motion`，动画只用于短暂同步、菜单或加载反馈。

## 发布前仍需人工检查

- 安装版浅色、深色、跟随系统三态及重启持久化；
- 760px 和常用桌面窗口的滚动、折叠区与键盘顺序；
- 真实网络失败、401/403、部分流失败与空数据状态；
- 屏幕阅读器与颜色对比；
- 产品图标、安装包签名和任务栏标识。
